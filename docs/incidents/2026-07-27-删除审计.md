# 事故复盘：反复「清理」误删汉化（2026-07-27）

> 这是仓库内部的事故记录，不是给玩家看的更新日志。
> 面向的问题是：一个 AI 协作者反复以「上游死重 / 游戏根本不读 / 改由 jar 现生成」
> 为由删掉汉化源文件，每次都自证清白，每次都要回滚。

## 全历史删除审计：恢复 1025 个文件，并上一道「只许加不许删」的硬闸

这个仓库到目前为止被删过 2000 余个文件，分八笔。每一笔的提交说明都是删的人
（本项目的 AI 协作者）自己写的结论——「上游死重」「游戏根本不读」「改由 jar
现生成」——而其中已经有两笔是专门回去救火的（`6d37e00`、`72a5cc8`），
这说明那套结论至少错过两次。

所以这次不看说明，按**内容**审（`scripts/audit_deletions.py`）：把每一笔删掉的
文件从父提交上取回来，抽出其中每一条含汉字的字符串（去掉颜色码与占位符后归一）
以及每一份二进制的 sha256，再拿去三处语料里找——今天的 `src/`、CI 刚构建出来的
出货包、整合包 482 个 mod jar 自带的官方中文。三处都找不到，才算真丢了。

结果：

- **四笔是真删错了**，共 1033 个文件，合计 30580 条中文当时在 `src/` 里查无此项。
  已按删除前的字节全部恢复（另有 8 个此前已被别的提交救回）。其中包括 230 份
  整份 `lang/zh_cn.json`、成套的 modopedia 图鉴页、Ars Nouveau 的 27 篇星辉兽
  词条、Modern Industrialization 导览书、Little Big Redstone 指南、MEGA Cells 导览
- **四笔查下来没丢东西**：生成物移出版本库（PNG 现生成，两边 zlib 版本不同、
  字节必不同，属预期）、资源蜜蜂搬去独立仓库、被撤销的机械合成产物、
  以及底本自带的说明文件
- **一笔要单独说**：`6a9f9b6` 删掉 17 份「重复覆盖官方汉化」的语言文件。逐键核过
  这 17 个命名空间，模组 jar 自带的官方中文**每个键都有、每条都是中文**，
  没有任何一处因此回退成英文；差别只在用词，而且官方那份更准
  （`terrace`→露台、`skyline`→天际线、`loft`→阁楼，被删的那份写的是
  「单梁」「铺架」「悬空」）

**闸**：`src/protected.json` 收录 `src/` 下全部文件，`scripts/protect.py --check`
挂在快闸与出货构建的最前面。删掉任何一个文件、或者把清单本身改短，CI 当场红。
真要删，得在 `released` 里留一条写明谁批准、为什么的永久记录——删除这件事从此在
版本库里留疤，而不是混在一笔「清理」提交的 500 个文件里。闸自己也有 10 条自检
（`scripts/test_protect.py`），含「容器里 git 用不了时不许崩、且照样拦得住」。

`verify_dist.py` 的导览书下限同理不再往下调：它这次正是先红了，才让人发现有 97 个
文件被删错，其中 39 篇是实打实的图鉴译文。

## 核实：已发布的 R12 没有玩家看得见的汉化缺口

R12 的包比上一版 `v7.2-release11` 小 824 KB，为此把两个包（含内层资源包 zip）
全部展开逐文件比对。release11 里含汉字、R12 里没有的文件共 513 个，逐个查了
所属命名空间在 ATM10 7.2 里是否真的存在——扫整合包 482 个 mod jar
（含 jar-in-jar 三层）的 `assets/` 与 `data/`，得 547 个命名空间；这个扫描器
拿已知真值验过：`6d37e00` 当年确认「靠 jar-in-jar 活着」的那 6 个全部识别为「在」。

结果：**511 个属于 232 个根本不在整合包里的模组**（底本汉化了一大批 ATM10
没有的模组，共 33194 条译文，游戏永远加载不到）；剩下 2 个一个是包内说明文档
（这一版改名叫「请安装前务必看我.md」，内容还在），一个是资源蜜蜂的**俄语**
路径下的书。**真缺口 0 个。**

同法核了当前构建与 R12 的差额：659 个文件里 405 个与模组自带的英文原页内容
完全相同（纯空壳，导览书本来就回落 en_us），254 个是模组 jar 自带同样的中文，
真缺口同样是 0。
